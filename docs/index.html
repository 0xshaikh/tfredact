A single Python CLI. Scan .tfstate and terraform plan output for credentials, write structurally identical copies with the secrets masked, and audit sensitive = true coverage. Zero runtime dependencies, no daemon, no network access, no configuration.

Three commands

tfredact scan <paths>

Finds secrets in state files, plan files and plan console logs. Prints resource address, attribute path, type, and whether Terraform had marked it sensitive. --json for CI aggregation.

tfredact redact <state>

Writes a structurally identical copy with secrets replaced by [REDACTED:type] markers. Same resources, same keys, valid JSON — diffs and review still work, the credential does not.

tfredact plan < plan.txt

Stdin-to-stdout filter for terraform plan console output. Preserves every line, line numbers, +/~ symbols and the summary — only the secret values change.

tfredact audit <dir>

Flags variable and output blocks that look like secrets but lack sensitive = true, plus literal secrets hardcoded in resource attributes. No HCL parser, no Terraform binary.

Precision-first detection

Two layers run in a deliberate order: precise value-shape matches first (AKIA..., PEM headers, JWT structure), then context typing from the attribute name and resource type — which is what catches a generated credential like Pr0d!AppDb2026#Secure that has no recognisable prefix at all. Generic entropy is the last resort and is never applied to known non-secret attributes.

base64_encoded_blob is not a terminal type: payloads are decoded and the decoded contents are scanned, so a password hidden inside a user-data script is reported as env_assignment_secret at its real offset rather than once as "some base64".

Built around a control fixture

The test suite encodes one rule that matters more than coverage: examples/clean.tfstate is packed with deliberately tricky non-secrets — RSA public keys, long ARNs, high-entropy KMS key material, DSNs with no credentials — and it must yield exactly zero findings. Every new detector has to survive it, so the scanner stays quiet on clean infrastructure.

Limitations, stated plainly

  • It is a scanner, not a policy engine. It cannot tell you whether a credential is valid, expired or already rotated — that requires calling the provider.
  • Detection is pattern-based. It will not find a secret stored under a name and shape that looks nothing like a secret, and there is no way to make it do so without accepting false positives.
  • sensitive = true is a logging control, not encryption. A secret Terraform believes is sensitive is still stored in full in the state file, and tfredact reports it as such rather than treating the marker as a fix.
